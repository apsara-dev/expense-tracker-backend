# FinTrack - Technical Interview Questions & Answers Guide

This guide is designed to help you confidently answer technical interview questions about your project, architecture decisions, frameworks used, and challenges you overcame.

---

## SECTION 1: Project Overview & Introduction (The Pitch)

### Q1: "Can you tell me about your project and its key highlights?"
**Answer:**
"I built **FinTrack**, a production-grade Full-Stack Personal Finance & Wealth Management web application. It helps users gain total visibility over their income and expenses through real-time KPI metrics, interactive Chart.js visualizations, and customizable monthly budget targets.

From an engineering perspective, the project features:
1. **A Decoupled Modern Architecture:** A React 19 Single Page App built with Vite communicating with a Django REST Framework (DRF) backend via secure RESTful APIs.
2. **Two-Factor Authentication (2FA):** User accounts are protected using a two-step login flow with time-sensitive (10-minute TTL) 6-digit OTPs delivered through responsive HTML email templates via Gmail SMTP.
3. **Stateless JWT Session Management:** Implemented using SimpleJWT with automated Axios request interceptors.
4. **Data Portability & Reporting:** Users can export structured Excel spreadsheets (`.xlsx`), generate printable PDF statements using `jsPDF` and `html2canvas`, or email summary reports directly from the server.
5. **Production Deployment:** Frontend is hosted on Vercel with SPA rewrite rules, and the backend is deployed as a live WSGI service on PythonAnywhere with an automated CI/CD deployment webhook."

## SECTION 2: React & Frontend Concepts

### Q2: "Why did you choose React 19 and Vite instead of traditional Create-React-App (CRA) or Next.js?"
**Answer:**
* **Why Vite over CRA:** Create React App is officially deprecated. Vite leverages native ES Modules (ESM) during development, providing instant server start times and sub-second Hot Module Replacement (HMR).
* **Why React SPA over Next.js:** FinTrack is an authenticated client dashboard where user data is private and dynamic. Server-Side Rendering (SSR) or Static Site Generation (SSG) does not offer significant benefits for private financial records behind an auth wall. A lightweight, performant React SPA paired with a dedicated REST API was the cleanest architectural choice.

### Q3: "How do you handle authentication state and protected routes on the frontend?"
**Answer:**
"We store the JWT `access` and `refresh` tokens in the browser's `localStorage`. In `src/api/axios.js`, an Axios request interceptor attaches the `Authorization: Bearer <token>` header to every outgoing HTTP request.
For route protection, when a user accesses the dashboard, the application checks for the token; if absent, it immediately redirects them to `/login`. Upon logging out or when a 401 Unauthorized status is returned, the tokens are purged and the user is redirected to the login screen."

### Q4: "How does the PeriodFilter component optimize data calculations?"
**Answer:**
"Instead of making redundant backend API calls for every minor filter tweak, the dashboard fetches the user's transaction records and utilizes React's **`useMemo` hook** to perform client-side filtering (e.g. Current Month, Last 30 Days, Year-to-Date, or Custom Range). `useMemo` ensures that expensive aggregations and Chart.js datasets are only recomputed when the raw transaction list or selected date filter actually changes."

### Q5: "How does client-side PDF and Excel export work?"
**Answer:**
* **Excel (`.xlsx`):** We use SheetJS (`xlsx`). We map the transaction state into tabular JavaScript objects, format currency and timestamps, create an in-memory workbook, and trigger a native browser file download.
* **PDF:** We capture the dashboard or statement DOM node using `html2canvas` at high DPI, convert the canvas into an image stream, and embed it into a multi-page PDF document generated by `jsPDF`."

## SECTION 3: Django & Backend Architecture

### Q6: "Why did you choose Django and Django REST Framework (DRF)?"
**Answer:**
"Django offers enterprise-grade security and robustness out of the box, including robust password hashing (PBKDF2), an object-relational mapper (ORM) that prevents SQL Injection, and cross-site scripting protections. Django REST Framework builds on top of this by providing clean Serializers, standard HTTP status codes, and declarative permission classes (`IsAuthenticated`, `AllowAny`)."

### Q7: "What is the difference between a Django Model and a Serializer?"
**Answer:**
* **Model:** Defines the database table structure, column types, relationships (foreign keys), and database constraints using Python code.
* **Serializer:** Acts as a bidirectional translator between complex Django ORM model instances and Python native datatypes (which are then serialized to JSON for HTTP responses). It also handles deserialization and validates incoming request data before saving."

### Q8: "How does the backend handle CORS (Cross-Origin Resource Sharing)?"
**Answer:**
"Because our frontend is hosted on a different origin (e.g. `http://localhost:5173` or `https://*.vercel.app`) than our backend (`https://apsarar.pythonanywhere.com`), browsers send a pre-flight `OPTIONS` request. We use the `django-cors-headers` package and place `corsheaders.middleware.CorsMiddleware` at the very top of Django's middleware pipeline. This attaches the appropriate `Access-Control-Allow-Origin: *` and allowed HTTP method headers to the response."

## SECTION 4: Authentication, Security & 2FA OTP

### Q9: "How did you design the 2-Factor Authentication (2FA) OTP system?"
**Answer:**
"We designed a two-step authentication handshake:
1. **Step 1:** The user submits their username/email and password. The backend calls Django's `authenticate()`. If valid, rather than issuing JWT tokens, the server calls `LoginOTP.generate_otp_for_user()`. This invalidates any prior unused OTPs, generates a cryptographically random 6-digit code, saves it with a timestamp, and dispatches an HTML email. The server returns `{ otp_required: true }`.
2. **Step 2:** The client prompts the user for the code and posts `{ username, otp }` to `/api/login/verify-otp/`. The server checks that the OTP matches, has not been used, and was created within the last 10 minutes (`datetime.timedelta(minutes=10)`). Once verified, `is_used` is set to `True` to prevent replay attacks, and JWT access/refresh tokens are returned."

### Q10: "How do you prevent brute force attacks on the OTP endpoint?"
**Answer:**
"Three levels of defense:
1. **Short Time-To-Live (TTL):** Each OTP expires in strictly 10 minutes.
2. **Single-Use Flag:** An OTP can only be used once (`is_used = True`).
3. **Resend Cooldown:** The frontend enforces a 45-second timer on the 'Resend Code' action, and the backend invalidates the old code whenever a new one is requested."

### Q11: "Why do you use JWT (JSON Web Tokens) instead of traditional Django sessions?"
**Answer:**
"Traditional Django sessions rely on cookies and server-side state stored in the database or Redis cache. For decoupled Single Page Applications and mobile apps, JWT is stateless. The backend does not need to look up a session ID in the database for every single authenticated request; it simply validates the token's cryptographic signature using the secret key."

## SECTION 5: Email Notification & Google SMTP

### Q12: "How does the application send real emails, and how did you configure SMTP?"
**Answer:**
"We configure Django's email backend to connect to `smtp.gmail.com` on port `587` with `EMAIL_USE_TLS = True`. Because Google requires 2-Step Verification for third-party applications, we generated a dedicated **16-character Google App Password** (`hdrnydnfkqxtxddw`). This allows our Django backend to authenticate with Google's SMTP servers securely without exposing account master credentials."

### Q13: "Why did you use HTML email templates instead of plain text?"
**Answer:**
"Plain text emails look generic, lack branding, and often get flagged as suspicious by modern mail filters. In `tracker/email_templates.py`, we built a responsive table-based HTML template with modern inline CSS. It features a branded header banner, large letter-spaced 6-digit OTP code badge, expiry warnings, and security tips, ensuring a high-trust, premium user experience across both desktop and mobile Gmail apps."

## SECTION 6: Real-World Troubleshooting & Challenges Overcame

### Q14: "What was a challenging bug you encountered in this project, and how did you fix it?"
**Answer:**
"We encountered a few significant real-world challenges:
1. **The Django Trailing Slash 500 Error:**
   * *Problem:* When the client sent a POST request to `/api/login` without a trailing slash, Django's `CommonMiddleware` triggered a `RuntimeError (500)` because it couldn't redirect a POST request while preserving body data.
   * *Solution:* We implemented dual routing in `tracker/urls.py` with both `path('login/', login_user)` and `path('login', login_user)` to accept both formats transparently.
2. **Google SMTP 'BadCredentials' Error:**
   * *Problem:* Initial email attempts failed with `535 5.7.8 BadCredentials`.
   * *Solution:* We isolated the issue using a minimal Python `smtplib` debugging script with `set_debuglevel(1)`. We discovered the previous app password had been revoked. We generated a fresh Google App Password, updated the backend settings and `.env`, and verified successful delivery.
3. **Vercel SPA 404 Routing:**
   * *Problem:* Refreshing the page on `/dashboard` in Vercel resulted in a 404 error.
   * *Solution:* Created `vercel.json` with a URL rewrite rule that forwards all non-asset requests back to `/index.html`, allowing React Router to handle client-side routing seamlessly."

### Q15: "Why did the PythonAnywhere deployment fail initially during git pull, and how was it solved?"
**Answer:**
"The PythonAnywhere server had untracked and modified local files in the working directory that conflicted with the incoming merge from GitHub, causing `git pull` to abort with error code 1.
We resolved this by executing `git reset --hard origin/main` in the server environment to align the working tree with the remote branch, applied database migrations, and touched the WSGI file to restart the worker processes."

## SECTION 7: Database & Performance

### Q16: "How did you design the database transactions for backup restoration?"
**Answer:**
"When a user restores a JSON backup containing dozens of transactions, we wrap the operation inside Django's `django.db.transaction.atomic()` context manager. This guarantees ACID compliance: if any single transaction record in the file is corrupted or fails validation, the entire batch rolls back, preventing partial or inconsistent data states."

### Q17: "What are the trade-offs of using SQLite, and how would you scale this in production?"
**Answer:**
* **SQLite Benefits:** Zero configuration, file-based, low memory footprint, and perfect for development and small-to-medium deployments.
* **Limitations:** SQLite locks the entire database file during writes, which can cause concurrency bottlenecks under heavy simultaneous write traffic.
* **Scaling Path:** In a high-traffic production environment, we would swap SQLite for **PostgreSQL** hosted on AWS RDS or Supabase, introduce a Redis caching layer for JWT and OTP storage, and utilize Gunicorn behind NGINX."

## SECTION 8: Rapid-Fire Technical Questions

| Question | Short Crisp Answer |
| :--- | :--- |
| **What is an Axios Interceptor?** | A middleware function that intercepts HTTP requests or responses before they are handled by `then` or `catch`, used here to inject the JWT Bearer token. |
| **What is PBKDF2?** | Password-Based Key Derivation Function 2; a key-stretching cryptographic hash algorithm designed to resist dictionary and brute-force attacks. |
| **What does `APPEND_SLASH` do in Django?** | Instructs Django to redirect URLs without a trailing slash to the slash-appended version if no URL pattern matches. |
| **What is WSGI?** | Web Server Gateway Interface; the standard Python specification for web servers (like Nginx/uWSGI) to communicate with web frameworks (like Django). |
| **What is the purpose of `is_used` in the OTP model?** | To ensure single-use validity and completely prevent replay attacks. |
| **What is HMR in Vite?** | Hot Module Replacement; updates modified JavaScript/CSS modules in the browser without reloading the entire page or losing component state. |
